## O que foi coberto (cronológico)

1. **Contexto**: tutoria para revisar conceitos básicos (porta de entrada para IA). Exercícios disponibilizados no Colab compartilhado.
2. **Exercício 1 — faixa etária**: ler nome e idade; classificar (criança <12, adolescente 12-17, adulto 18-64, idoso >64).
   - `input` sempre retorna **string**; `int()` faz casting quando necessário (nome fica string).
   - `if ... elif ... else` para desvios; `=` após operador inclui as bordas (12-17 inclui 12 e 17).
   - F-string: variáveis entre `{}` com `f` antes das aspas para strings com partes dinâmicas.
   - **elif vs. if**: `elif` interrompe nas primeiras condições verdadeiras (não testa as demais) — boas para condições mutuamente exclusivas; com `if` repetido todas seriam testadas.
   - **Tratamento de entrada**: `try/except` (tentar converter; se falhar, tratar). O except genérico pega "qualquer erro"; erros específicos podem ser nomeados (ex.: `ValueError`).
   - **Repetição until válido**: `while not idade_valida:` com variável booleana inicializada `False`; dentro, tenta ler e converte; no sucesso marca `idade_valida = True`; senão "idade inválida, digite novamente" (repetir). Alternativa citada: `while True` + `break`.
   - Exercício extra: tratar idade negativa (nova categoria tipo "bebê").
3. **Exercício 2 — função com lista**: função que recebe lista de inteiros e retorna soma dos elementos pares em posições ímpares (indexação a partir de 0).
   - **Funções**: `def` + nome significativo (evitar `f`, `x`, `a` — usar nomes que representem o conteúdo), corpo indentado, `return`. Definir ≠ executar: só roda quando chamada.
   - **Listas**: delimitador `[]`, elementos separados por vírgula, indexação a partir de 0 (`lista[0]` é o primeiro). Python permite listas heterogêneas; parte decimal usa ponto.
   - **Percorrer**: `for i in range(len(lista))` — `len` é função nativa; `range(n)` vai de 0 a n-1.
   - **Acumular**: `soma = soma + lista[i]` ou `soma += lista[i]`.
   - **Condições**: par = `lista[i] % 2 == 0` (operador módulo); posição ímpar = `i % 2 == 1`.
   - Aninhar `if` dentro de `if`, OU combinar com `and` (formas equivalentes; `and` recomendado por deixar o código sem indentação excessiva). Ordem das condições não muda resultado; nuances de performance desprezíveis.
4. **Dúvidas (origem COBOL/Pascal)**:
   - **Sem `endif` no Python**: controle por **escopo/indentação** (blocos de 4 espaços, `:`). `else`/`elif` encerram um bloco; um `if` dentro de outro é indicado por indentação. Quando a indentação volta à esquerda, o bloco acabou.
   - É possível aninhar `if`/`else`/`elif` dentro de `if` — o que na sintaxe COBOL seria `endif`, aqui é a indentação (sugestão: usar `end if`/comentários ou fluxograma como apoio no começo).
   - **Desempenho**: escrever em 1 linha vs. várias linhas não muda performance de forma significativa; legibilidade é prioridade no Python.
5. **Fechamento**: mais exercícios preparados ficam como extra para as próximas tutorias / fórum; notebook e gravação divulgados no Moodle (sessão "tutorias").

## Pontos-chave / Decisões

- `input` → string; usar `int()`/`float()` para conversão; `try/except` para entradas inválidas.
- `if`/`elif`/`else` para desvios; `elif` evita testar condições desnecessárias.
- F-string para strings com partes variáveis.
- `while not condicao` + flag booleana para repetir até entrada válida (ou `while True` + `break`).
- Funções: `def nome(param)`, corpo indentado, `return`; nomes devem descrever o conteúdo.
- Lista: `[]`, indexação de 0; `for i in range(len(lista))`; `+=` acumula.
- Par/ímpar com operador módulo `%`.
- `and` combina condições (equivale a aninhar `if`).
- Python: blocos por indentação (sem `endif`/`begin`/`end`).
- Não há ganho de performance relevante entre formas de escrita — priorize legibilidade.
